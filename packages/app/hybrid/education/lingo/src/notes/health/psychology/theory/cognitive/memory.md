## Memory is not one thing

Before asking how memory works it helps to ask which memory. Psychologists
separate along three independent axes.

By **content**, long-term memory divides into _declarative_ — facts and episodes
you can state — and _procedural_, the skills and habits you cannot. Riding a
bicycle is stored; describing how you ride one is not.

By **consciousness**, some memory is _explicit_: retrieval is a deliberate act
and you know you are doing it. Other memory is _implicit_: it changes your
behaviour without ever surfacing as a thought. Priming — having seen _bread_
makes _butter_ easier to recognise a moment later — is memory at work with no
memory experience at all.

By **stage**, information passes through sensing, then short-term retention,
then encoding into long-term storage, and finally retrieval, each stage a
separate chance to lose it.

The axes do not line up. Skill learning is both procedural and implicit.
Recalling an episode is declarative and explicit. Knowing that practice helps
skill learning is declarative memory about procedural memory.

## Working memory is capacity, not storage

Working memory is a small, temporary store — able to hold roughly four items,
not the seven Miller famously reported. Miller's magic number came from the span
of **absolute judgement** under ideal conditions, presented one item at a time;
real-world **chunking** rarely yields more than three or four chunks.

Cowan's refinement adds that the number is fragile: holding four chunks is
possible for about ten seconds, and any interfering task empties it. That
emptying is the mechanism behind most "I was listening but lost the thread"
failures.

Baddeley's model separates the system into a **central executive** that directs
attention, a **phonological loop** for speech and sound, a **visuospatial
sketchpad** for images and locations, and an **episodic buffer** that binds them
into a coherent scene.

Change one component and the pattern of error changes. Ask people to repeat
digits and they fail on length. Ask them to match columns of letters while
reciting spoken words and they succeed at both — two independent systems, two
independent failures.

## Encoding decides whether anything is stored

Nothing is stored just because it was seen. Encoding is a filter, and its
strictness varies with processing depth.

The **levels of processing** framework ranks shallow and deep treatments:
reading a word aloud for meaning is more fragile than deciding whether it fits a
sentence, which is more fragile than imagining a picture of yourself using the
thing. Deep processing wins not because it is effortful but because it leaves
more distinct routes back to the memory.

Three practical levers follow. **Chunking** compresses nine digits into three
triads, which is why _123,456,789_ beats nine separate digits. **Elaboration**
adds connections to what is already known, so _learning π through the Feynman
technique_ survives longer than _learning π_. **Distinctiveness** adds a
retrieval cue: an unusual image or a vivid detail gives recall somewhere to hook
on to.

## The shape of forgetting

Forgetting is fast at first and then slow. Ebbinghaus's nonsense syllables fell
by more than half within the first hour and then flattened — most loss happens
immediately, and what survives an hour survives far longer.

Free recall of a list produces the **serial position curve**: items at the start
(_primacy_) and end (_recency_) are recalled best, the middle worst. Primacy
reflects rehearsal, which moves items into long-term memory. Recency reflects
the items still sitting in working memory, unprocessed. Run the same task with a
delay inserted and the recency advantage disappears — a clean demonstration that
two mechanisms produce one curve.

Two effects beat almost everything else when you are studying. The **spacing
effect**: long gaps between attempts outperform equal effort crammed together,
across syllables, lists, and real exam material. The **testing effect**: pulling
information out of memory strengthens it more than rereading it, even when the
rereading feels more effective. Retrieval is the learning event; the review
session is only practice for it.

## Recall reconstructs, it does not replay

Each act of recall is partly a construction. Retrieved traces are integrated
into existing knowledge, and the integration can overwrite details that no
longer fit.

Loftus's misinformation experiments made this concrete: participants who saw a
car broken glass, then later read about a sale, later reported having seen the
sale in the original footage. The error is not a lie told deliberately; it is
what a reconstructive system produces when the reconstruction is repeated under
slightly different instructions.

Reconsolidation — the window after recall in which a memory is temporarily
labile again — is the mechanism that makes this possible. Each reactivation
rewrites the trace, and the rewrite is guided by whatever is in mind right now.

## The drills on this page

Four games, four things memory does, deliberately separated.

**Pi** removes structure entirely. The digits have no regularity to chunk, no
meaning to elaborate, no distinctiveness — the only route is raw sequential
memorisation, and a single wrong digit costs the run. It is the control
condition.

**Recall** varies the length of a list you have to hold, which is the cleanest
demonstration of digit span and of primacy and recency: the digits you saw first
and last are the ones you keep.

**Memory Match** is associative rather than serial. You never learn a path
through the grid; you search a set of locations and match pairs. Spreading a
matching pair across the grid is exactly what the serial position findings
predict, and a larger grid lengthens the search without lengthening the list.

**N-Back** is the one drill here that is not memory storage at all. It measures
how reliably you update — discarding the stimulus n steps back and keeping only
the current one. It is the closest thing here to a laboratory measure of working
memory, and its accuracy falls steeply as n rises, because you are being asked
to hold one item while constantly overwriting it.
