# Start

Start page bookmark launcher — renders bookmark sections as tool cards from a
CSV-driven data pipeline.

## Data Workflow

`data/bookmarks.csv` is the single source of truth. Edit it (in a spreadsheet or
text editor), then regenerate the JSON the app consumes:

```bash
ts-node --project scripts/tsconfig.json \
  src/components/routes/start/data/scripts/convert-csv-to-json.ts
```

- Never edit `data/bookmarks.json` by hand — it is generated from the CSV.
- `data/bookmarks.ts` maps icon name strings (e.g. `PiStarFour`) to
  `react-icons/pi` components and exports `BOOKMARK_SECTIONS`.
- Add bookmarks to the CSV only; run the script to regenerate.

## Build & Test

```bash
pnpm dev            # Start Next.js dev server
pnpm test           # Run all Jest tests
pnpm tsc --noEmit   # TypeScript type check
pnpm lint           # ESLint
```

## File Structure

```txt
src/components/routes/start/
  index.tsx                    # Route entry — renders AppsStoreTemplate
  AGENTS.md
  data/
    bookmarks.csv              # Source of truth (edit this)
    bookmarks.json             # Generated by scripts/convert-csv-to-json.ts
    bookmarks.ts               # Loads JSON -> BOOKMARK_SECTIONS with icon resolution
    scripts/
      convert-csv-to-json.ts   # CSV -> JSON converter (see Data Workflow above)
```

## CSV Schema

Columns: `section,label,description,href,icon,badge`

- `section` — group label; rows sharing a value group together in order
- `label` — visible tool name
- `description` — subtitle shown under the label
- `href` — destination URL
- `icon` — `react-icons/pi` component name as a string (e.g. `PiCalendar`)
- `badge` — optional small pill text; leave empty for none

`icon` names must exist in the `ICON_BY_NAME` map in `data/bookmarks.ts`; add
new icons there when introducing them.

## Coding Rules

1. Arrow functions only — no `function` keyword
2. Explicit types on all exports — never `any`
3. Icons: `react-icons/pi` (Phosphor) only
4. TailwindCSS v4 + DaisyUI v5 — no CSS modules, no styled-components
5. Keep files under 200 lines, functions under 30 lines
6. `BOOKMARK_SECTIONS` consumes `data/bookmarks.json` — never hardcode bookmarks
   in components
7. Test behaviour, not implementation — Jest + Testing Library
8. Mobile-first responsive design
