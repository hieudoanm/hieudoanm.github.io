# Apps

## Data Workflow

`data/apps.csv` is the single source of truth. Edit it (in a spreadsheet or text
editor), then regenerate the JSON the app consumes:

```bash
ts-node --project scripts/tsconfig.json \
  src/components/routes/apps/data/scripts/convert-csv-to-json.ts
```

- Never edit `data/apps.json` by hand — it is generated from the CSV.
- `data/apps.ts` maps icon name strings (e.g. `PiMagnifyingGlass`) to
  `react-icons/pi` components and exports `APP_SECTIONS` plus
  `getAppSections()`.
- Add apps to the CSV only; run the script to regenerate.

## CSV Schema

Columns: `section,sectionId,label,description,icon,toolId`

- `section` — group label; rows sharing a value group together in order
- `sectionId` — URL slug for the section (`/apps/<sectionId>/<toolId>`); use the
  same value on every row of the section
- `label` — visible tool name
- `description` — subtitle shown under the label
- `icon` — `react-icons/pi` component name as a string (e.g. `PiClock`)
- `toolId` — URL slug for the tool (`/apps/<sectionId>/<toolId>`)

`icon` names must exist in the `ICON_BY_NAME` map in `data/apps.ts`; add new
icons there when introducing them.

## Build & Test

```bash
pnpm dev          # Start Next.js dev server
pnpm test         # Run all Jest tests
pnpm jest -- "AppName"  # Run tests for a specific app
pnpm tsc --noEmit # TypeScript type check
pnpm lint         # ESLint
```

## File Structure

```
apps/<category>/
  index.tsx          # Component entry (default export)
  <SubComponent>.tsx # Sub-components
  utils.ts           # Logic/types (pure functions only)
  __tests__/
    index.test.tsx   # Component + behaviour tests
```

```
src/components/routes/apps/
  index.tsx                    # Route entry — renders AppsStoreTemplate
  AGENTS.md
  data/
    apps.csv                   # Source of truth (edit this)
    apps.json                  # Generated by scripts/convert-csv-to-json.ts
    apps.ts                    # Loads JSON -> APP_SECTIONS with icon resolution
    scripts/
      convert-csv-to-json.ts   # CSV -> JSON converter (see Data Workflow above)
```

## Coding Rules

1. Arrow functions only — no `function` keyword
2. Explicit types on all exports — never `any`
3. State management: `useState`/`useReducer` for local, React Context for shared
4. TailwindCSS v4 + DaisyUI v5 — no CSS modules, no styled-components
5. Icons: `react-icons/pi` (Phosphor)
6. Each tool component receives `onClose: () => void` prop
7. Keep files under 200 lines, functions under 30 lines
8. Pure logic in `utils.ts` — never mix UI and business logic
9. Test behaviour, not implementation — Jest + Testing Library
10. `APP_SECTIONS` consumes `data/apps.json` — never hardcode app sections in
    components

## Route Pattern

Every app tool needs two files:

```
src/app/(products)/apps/<category>/<tool>/page.tsx
src/components/routes/apps/<category>/<Tool>/index.tsx
```

```tsx
// page.tsx
'use client';
import { ToolPage } from '../../_shared/ToolPage';
import { MyTool } from '@hieudoanm.github.io/components/routes/apps/<category>/<MyTool>';
const Page = () => <ToolPage Component={MyTool} backPath="/apps/<category>" />;
export default Page;
```

## Registering New Tools

Add entry in `src/components/routes/start/types.ts` (`MODAL_IDS` array) and in
`src/app/(products)/apps/_shared/_maps.ts`.

## State Management

- Prefer pure functions with explicit dependencies
- No global/singleton state — pass dependencies explicitly
- Return values over side effects
