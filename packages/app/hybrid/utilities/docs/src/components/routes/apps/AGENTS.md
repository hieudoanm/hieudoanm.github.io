# Apps

Merged apps + bookmarks home page. The root route `/` renders
`getHomeSections()` (bookmark sections followed by app sections). App categories
are flattened one level under root: `<category>/<tool>` (no `/apps` prefix).

## Data Workflow

A single unified CSV drives this route: `data/apps.csv`. It is the single source
of truth. Edit it, then regenerate the JSON the app consumes:

```bash
ts-node --project scripts/tsconfig.json \
  src/components/routes/apps/data/scripts/convert-csv-to-json.ts
```

- Never edit `data/apps.json` by hand — it is generated from the CSV.
- `data/apps.ts` maps icon name strings (e.g. `PiMagnifyingGlass`) to
  `react-icons/pi` components and exports `APP_SECTIONS`, `getAppSections()`,
  and `getHomeSections()`.
- Add apps/bookmarks to the CSV only; run the script to regenerate.

The CSV holds both **bookmark rows** (external links) and **app rows** (internal
routes) — see the schema below.

## CSV Schema

Columns: `section,sectionId,label,description,icon,toolId,href,badge`

- `section` — group label; rows sharing a value group together in order
- `sectionId` — URL slug for the app section (`/<sectionId>/<toolId>`); only set
  on app rows, empty on bookmark rows
- `label` — visible tool / bookmark name
- `description` — subtitle shown under the label
- `icon` — `react-icons/pi` component name as a string (e.g. `PiClock`)
- `toolId` — URL slug for the tool (`/<sectionId>/<toolId>`); only set on app
  rows, empty on bookmark rows
- `href` — destination URL; only set on bookmark rows, empty on app rows
- `badge` — optional small pill text; leave empty for none (bookmarks usually)

A row is a **bookmark** if it has an `href`; it is an **app** if it has
`sectionId` + `toolId`. Every row must be exactly one of these.

`icon` names must exist in the `ICON_BY_NAME` map in `data/apps.ts`; add new
icons there when introducing them. Add new icons to both the import list and the
`ICON_BY_NAME` map.

## Build & Test

```bash
pnpm dev          # Start Next.js dev server
pnpm test         # Run all Jest tests
pnpm jest -- "AppName"  # Run tests for a specific app
pnpm tsc --noEmit # TypeScript type check
pnpm lint         # ESLint
```

## File Structure

```
apps/<category>/
  index.tsx          # Component entry (default export)
  <SubComponent>.tsx # Sub-components
  utils.ts           # Logic/types (pure functions only)
  __tests__/
    index.test.tsx   # Component + behaviour tests
```

```
src/components/routes/apps/
  AGENTS.md
  data/
    apps.csv                   # Source of truth — apps + bookmarks (edit this)
    apps.json                  # Generated by scripts/convert-csv-to-json.ts
    apps.ts                    # Loads JSON -> APP_SECTIONS / getHomeSections
    scripts/
      convert-csv-to-json.ts   # apps.csv -> apps.json
```

## Coding Rules

1. Arrow functions only — no `function` keyword
2. Explicit types on all exports — never `any`
3. State management: `useState`/`useReducer` for local, React Context for shared
4. TailwindCSS v4 + DaisyUI v5 — no CSS modules, no styled-components
5. Icons: `react-icons/pi` (Phosphor)
6. Each tool component receives `onClose: () => void` prop
7. Keep files under 200 lines, functions under 30 lines
8. Pure logic in `utils.ts` — never mix UI and business logic
9. Test behaviour, not implementation — Jest + Testing Library
10. `APP_SECTIONS` / `getHomeSections()` consume the JSON in `data/` — never
    hardcode app sections in components

## Route Pattern

Every app tool needs two files:

```
src/app/(products)/<category>/<tool>/page.tsx
src/components/routes/apps/<category>/<Tool>/index.tsx
```

```tsx
// page.tsx
'use client';
import { useRouter } from 'next/navigation';
import { MyTool } from '@hieudoanm.github.io/components/routes/apps/<category>/<MyTool>';

const Page = () => {
  const router = useRouter();
  return <MyTool onClose={() => router.push('/<category>')} />;
};
export default Page;
```

## Registering New Tools

Add the app row to `data/apps.csv` and run the converter, then create the two
files in the Route Pattern above.

## State Management

- Prefer pure functions with explicit dependencies
- No global/singleton state — pass dependencies explicitly
- Return values over side effects
