# US-007: Convert DBML via the MCP server

## Story

**As a** developer
**I want** dbml to expose its conversion tools through the Model Context Protocol
**So that** an LLM client in my editor can generate SQL, diagrams, or a schema summary from DBML I am working on

## Acceptance scenarios

- **Given** the MCP client configuration from [`README.md`](../README.md) (`"command": "dbml", "args": ["mcp", "serve"]`), **When** the client launches the server, **Then** the `initialize` exchange succeeds with protocol version `2024-11-05` and `serverInfo` naming `dbml`.
- **Given** an initialised session, **When** the client sends `tools/list`, **Then** exactly four tools are returned: `dbml_sql`, `dbml_mermaid`, `dbml_svg`, and `dbml_parse`, each requiring a `dbml` string argument.
- **Given** a `tools/call` to `dbml_sql` with a multi-line `Table users` block, **When** the tool runs, **Then** the response contains one text item whose content includes `CREATE TABLE users` and `PRIMARY KEY`.
- **Given** the same DBML source, **When** it is converted through MCP and through `dbml sql` on the CLI, **Then** the generated text is identical — one parser, one generator, three transports.
- **Given** a `tools/call` with a blank `dbml` argument, **When** it is handled, **Then** the response is a JSON-RPC error with code `-32603` and the message `dbml argument is required`, and the server keeps serving subsequent requests.

## Notes

- The protocol surface (`initialize`, `ping`, `tools/list`, `tools/call`, notification handling, error codes) is specified in [`FEATURE-07-MCP-Server.md`](../02-features/FEATURE-07-MCP-Server.md).
- The `dbml` argument must be multi-line DBML: a one-line block such as `Table users { id integer [pk] }` (used in the request examples of [`06-api-specification.md`](../06-api-specification.md) §6) is never committed by the parser and converts to an empty schema ([`FEATURE-01-DBML-Parsing.md`](../02-features/FEATURE-01-DBML-Parsing.md) §5).
- The MCP server is a **P1** enhancement ([`README.md`](../README.md) §4); the CLI and HTTP paths are the P0 core.
- The `dbml_parse` tool returns a JSON summary (project name, tables with column names, enums, references) rather than generated DDL — useful as context for a language model.
