# US-002: Generate SQL DDL from DBML

## Story

**As a** developer
**I want** to generate PostgreSQL-compatible SQL DDL from a DBML file
**So that** I can use it in migrations, CI pipelines, and database setups

## Acceptance scenarios

- **Given** `schema.dbml` with primary-key, unique, not-null, and default columns, **When** `dbml sql schema.dbml -o schema.sql` runs, **Then** `schema.sql` contains one `CREATE TABLE` per table with those constraints inline, and stdout reports `Generated SQL schema: schema.sql`.
- **Given** no `-o` flag, **When** `dbml sql schema.dbml` runs, **Then** the output is written to `initial_schema.sql` in the current directory.
- **Given** a named relationship `Ref: user_posts users.id < posts.user_id`, **When** SQL is generated, **Then** the output includes `ALTER TABLE posts ADD CONSTRAINT user_posts FOREIGN KEY (user_id) REFERENCES users(id);`.
- **Given** a table containing `Index unique (user_id, email)`, **When** SQL is generated, **Then** the table's `CREATE TABLE` includes `UNIQUE (user_id, email)`.
- **Given** a column typed `varchar(100)`, **When** SQL is generated, **Then** the type renders as `VARCHAR(100)`.

## Notes

- The full output contract — header comment, type mapping, constraint order, foreign-key placement — is specified in [`FEATURE-02-SQL-Generation.md`](../02-features/FEATURE-02-SQL-Generation.md).
- Generated SQL is deterministic, so re-running the command on unchanged input rewrites an identical file (reproducibility, [`12-operations.md`](../12-operations.md)).
- Executing the DDL against a real PostgreSQL is a stated success criterion ([`00-overview.md`](../00-overview.md) §11), but real-database integration tests are not yet in CI ([`README.md`](../README.md) §8).
