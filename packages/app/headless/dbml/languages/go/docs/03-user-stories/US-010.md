# US-010: Handle malformed DBML input

## Story

**As a** developer
**I want** bad or unreadable input to be handled predictably on every transport
**So that** I learn what is wrong instead of receiving silent or misleading output

## Acceptance scenarios

- **Given** a file path that does not exist, **When** `dbml sql missing.dbml` runs, **Then** stderr contains `dbml: parse DBML: open file: ...` naming the path, and no partial output is written.
- **Given** a DBML file with a single line beyond the parser's scan buffer, **When** conversion runs, **Then** the run fails with a `scan error: ...` message instead of producing a truncated schema.
- **Given** `POST /api/v1/convert` with `{"dbml":""}`, **When** the server replies, **Then** the status is 400 with `{"error":"dbml field is required"}`.
- **Given** a multipart request containing neither a `file` nor a `dbml` field, **When** the server replies, **Then** the status is 400 with `{"error":"no dbml content found in multipart request"}`.
- **Given** a `tools/call` with only whitespace in `arguments.dbml`, **When** the MCP server replies, **Then** the JSON-RPC error is `-32603` with `dbml argument is required`, and later requests still succeed.
- **Given** readable but structurally odd input (for example a mistyped block header), **When** conversion runs, **Then** the parser skips the lines it cannot classify and completes with the remaining schema — strict grammar rejection is not guaranteed today.

## Notes

- The last scenario is the documented limitation of a tolerant, line-based parser: unreadable input fails loudly, unclassifiable input is skipped (see [`FEATURE-01-DBML-Parsing.md`](../02-features/FEATURE-01-DBML-Parsing.md) edge cases and [`FEATURE-08-Error-Handling.md`](../02-features/FEATURE-08-Error-Handling.md)).
- The contributor guideline "do not silently ignore malformed input" is the direction of travel for this story; today's guarantees are the transport-level validations listed above.
- Every rejection path returns an actionable message with no filesystem paths or internals in API responses ([`06-api-specification.md`](../06-api-specification.md) §1).
- dbml is a software demonstration — this story covers the malformed-input behaviour it actually implements, not a formal DBML validator.
