# US-003: Generate a Mermaid ER diagram from DBML

## Story

**As a** developer
**I want** to generate a Mermaid `erDiagram` from a DBML file
**So that** I can embed an entity-relationship diagram in Markdown documentation

## Acceptance scenarios

- **Given** `schema.dbml` with tables and columns, **When** `dbml mermaid schema.dbml` runs, **Then** `database-erd.mmd` is written containing an `erDiagram` header and one block per table, and stdout reports `Generated Mermaid ER diagram: database-erd.mmd`.
- **Given** columns marked `pk`, `unique`, and `not_null`, **When** the diagram is generated, **Then** their rows carry the `PK`, `UK`, and `NOT NULL` markers respectively.
- **Given** the relationship `Ref: user_posts users.id < posts.user_id`, **When** the diagram is generated, **Then** it contains the line `users ||--o{ posts : "user_posts"` naming both tables and the reference.
- **Given** `-o diagram.mmd`, **When** `dbml mermaid schema.dbml -o diagram.mmd` runs, **Then** the diagram is written to `diagram.mmd` instead of the default name.
- **Given** the generated file, **When** it is embedded in a GitHub or GitLab Markdown page, **Then** it renders as an ER diagram without dbml invoking any renderer itself.

## Notes

- Output shape and edge cases (fixed `||--o{` cardinality, enums not rendered) are specified in [`FEATURE-03-Mermaid-Generation.md`](../02-features/FEATURE-03-Mermaid-Generation.md).
- The same diagram is available over HTTP (`formats: ["mermaid"]`) and through the MCP tool `dbml_mermaid` — one generator, three transports ([`04-architecture.md`](../04-architecture.md) §2).
- Rendering in GitHub/GitLab is a success criterion of [`00-overview.md`](../00-overview.md) §11.
