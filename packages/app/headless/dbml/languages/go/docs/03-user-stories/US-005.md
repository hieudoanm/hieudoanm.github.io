# US-005: Generate all formats at once

## Story

**As a** developer
**I want** one command that produces SQL, Mermaid, and SVG together
**So that** I can update every artifact from a single DBML source in one step

## Acceptance scenarios

- **Given** `schema.dbml` in the current directory, **When** `dbml all schema.dbml --output-dir ./output` runs, **Then** `./output/` contains `initial_schema.sql`, `database-erd.mmd`, and `schema.svg`, and stdout lists one `Generated ...:` line per file.
- **Given** `./output` does not exist, **When** `dbml all` runs with `--output-dir ./output`, **Then** the directory is created (`0755`) and the run exits 0.
- **Given** no flags, **When** `dbml all` runs, **Then** all three artifacts are written to the current directory (default `-d .`).
- **Given** previously generated artifacts in the output directory, **When** `dbml all` runs again on unchanged input, **Then** the files are overwritten with byte-identical content, making the command repeatable.
- **Given** the output directory is not writable, **When** `dbml all` runs, **Then** stderr names the step that failed (`dbml: create output dir: ...` or `dbml: write ...: ...`); the exit status is currently 0 (see [`FEATURE-08-Error-Handling.md`](../02-features/FEATURE-08-Error-Handling.md) §5).

## Notes

- The file names are fixed by the implementation: `initial_schema.sql`, `database-erd.mmd`, `schema.svg` — the output directory is the only choice the command needs (zero-config, [`00-overview.md`](../00-overview.md) §3).
- The input is parsed once and the same AST feeds all three generators ([`04-architecture.md`](../04-architecture.md) §6).
- This command is the canonical "product promise" workflow: DBML in, SQL + diagram + diagram out ([`README.md`](../README.md) §5, Journey A).
