# Organization and Metadata

## Structure

Choose a predictable project layout that distinguishes original/source material, derived data, code, documentation, and outputs. Use stable identifiers and consistent names; avoid names that encode sensitive information. Document the structure and avoid relying on undocumented personal conventions.

## File naming

Use names that are unique, sortable where useful, and meaningful without embedding personal data. Define separators, date format, version strategy, and allowed characters. Do not use ambiguous labels such as `final-final2`.

## Metadata

Document what each file contains, its source, units, encoding, collection date or period, transformations, missing-value representation, and relevant rights or access limits. A data dictionary should define variables, labels, valid values, units, and derivation rules.

Select community standards when they fit the discipline; do not force a standard that loses essential context. Keep metadata close to the data and in a durable, machine-readable form where practical.
