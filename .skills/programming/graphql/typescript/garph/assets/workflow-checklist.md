# garph: Workflow Checklist

A practical run sheet for applying [garph](../SKILL.md). Tailor each item to the current project and record evidence where the decision matters.

## Before starting

- [ ] Confirm the task is within this skill's scope.
- [ ] Check applicable versions, project conventions, and prerequisites.
- [ ] Define a measurable outcome and relevant constraints.

## Apply the skill

- [ ] 1. Core Concepts: **Schema-first in TS**: use Garph types (g.string(), g.int(), g.ref(...)) to build schema directly — the TS types are generated by reading the schema at compile-time, no CLI/codegen
- [ ] 1. Core Concepts: **Automatic inference**: TypeScript infers the types for resolvers from the schema object (g.type(...)) — wrong resolver signatures fail compilation
- [ ] 2. Setup: Deps: garph, graphql, and a server adapter (pairs with graphql-yoga or an HTTP server via graphql)
- [ ] 2. Setup: Build a g.schema(...) and a resolver map, then g.resolve() to get executable schema
- [ ] 3. Definitions: Scalars: g.string(), g.int(), g.float(), g.boolean(), g.id()
- [ ] 3. Definitions: Types: g.type('User', { name: g.string(), age: g.int().optional() }) (Nullable/optional modifiers)
- [ ] 4. Resolvers: Pass a resolver map aligned with schema keys: const resolvers = { Query: { hello: () => 'hi' } }
- [ ] 4. Resolvers: Typed args: read args from resolver signature — TS knows their types
- [ ] 6. Common Pitfalls: Forgetting the resolver shape must mirror schema exactly (untyped key mismatch → runtime error or TS error)
- [ ] 6. Common Pitfalls: Relying on implicit any in inference for unions/interfaces loops — write them explicitly when tricky

## Complete the work

- [ ] Review tradeoffs and failure cases before adopting the result.
- [ ] Run the validation appropriate to the change.
- [ ] Record important assumptions and deviations for future maintainers.
