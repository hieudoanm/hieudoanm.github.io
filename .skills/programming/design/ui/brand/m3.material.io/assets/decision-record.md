# Google Design System (Material Design 3): Decision Record

Use this record when applying [Google Design System (Material Design 3)](../SKILL.md) to a concrete project decision.

## Context

Build web/app UI on an inherited, opinionated design system (Material Design 3 / Google) instead of inventing tokens from scratch. Covers color roles, type and shape scales, elevation, state layers, motion tokens, Tailwind v4 + DaisyUI 5 wiring, and where divergence must be declared. Use when starting a new app, choosing between borrowing a system and deriving one, or reviewing UI that drifts from its own design system.

Every product ends up with a design system. The question is whether you **inherit** one or **derive** one from content (see design/brand/nothing.md). Mixing the two is the usual reason UI feels inconsistent with no explainable cause. This skill covers the inherit branch, using M3 because its token model is role-based and maps cleanly onto CSS variables, Tailwind v4, and DaisyUI 5.
