# Context Modeling

Start with a bounded system and its users, external systems, and important interactions. State what is inside the scope and what remains an external dependency.

For each interaction, identify initiator, purpose, data exchanged, protocol or channel where known, owner, trust relationship, and failure impact. Mark unknown or inferred relationships explicitly and validate them with system owners.

Keep a context diagram readable and at a consistent level of abstraction. Do not mix classes, services, vendors, and business actors in one undifferentiated view. Link deeper container or flow diagrams for detail.
