# Trust Boundaries

Mark where identity, privilege, data sensitivity, or administrative control changes. For each crossing, identify the actor, assets, threat assumptions, authentication and authorization checks, validation, encryption, logging, and failure behavior.

Do not treat network location as sufficient trust. Review service-to-service identity, least privilege, secrets, third-party dependencies, and administrative paths. Consider data in transit, at rest, and in logs or telemetry.

The boundary diagram is an input to threat modeling, not a complete security assessment. Validate it with security owners and update it when integrations, tenancy, or data flows change.
