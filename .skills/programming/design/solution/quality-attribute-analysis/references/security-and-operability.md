# Security and Operability

Translate security and privacy obligations into scenarios tied to assets, trust boundaries, actors, and threat assumptions. Define required controls and evidence: authentication, authorization, encryption, audit, retention, secrets handling, vulnerability response, and recovery.

Define operability through ownership, health signals, actionable alerts, runbooks, deployment and rollback, backup verification, and incident escalation. Observability should support questions operators need to answer without exposing sensitive data.

Security and operational reviews are continuous activities. Identify accountable owners and required specialist review; do not claim compliance or security from an architecture diagram alone.
