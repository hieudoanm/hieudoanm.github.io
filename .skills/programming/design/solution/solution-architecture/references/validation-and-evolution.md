# Validation and Evolution

Validate the highest-risk assumptions first. Select evidence proportional to impact and reversibility: prototypes, load tests, security review, dependency checks, failure injection, data migration rehearsals, or operational exercises.

Plan implementation slices with observable outcomes and safe rollback. Define migration sequencing, compatibility windows, data reconciliation, cutover criteria, and retirement of old paths. Include monitoring and support ownership.

Architecture evolves. Record decision triggers such as workload, cost, compliance, or ownership changes. Review decisions when evidence changes rather than treating the original target as permanent. Capture operational feedback and actual quality measures after launch.
