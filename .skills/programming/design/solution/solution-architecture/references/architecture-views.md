# Architecture Views

Choose views that answer stakeholder questions. A small set of consistent diagrams is more useful than a large catalog with no decision context.

- **Context:** users, external systems, scope, and key interactions.
- **Container/component:** deployable units or major responsibilities, ownership, and dependencies.
- **Sequence/data flow:** important use cases, trust boundaries, and failure paths.
- **Deployment:** runtime locations, network zones, scaling, and operational ownership.
- **Data:** authoritative sources, lifecycle, retention, and flows.

Label scope, systems, protocols, and uncertainty. Keep diagrams synchronized with written decisions and current implementation; distinguish current state from proposed state. A diagram is a view, not the architecture itself.
