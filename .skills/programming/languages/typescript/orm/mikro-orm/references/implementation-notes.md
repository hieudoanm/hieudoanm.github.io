# Implementation notes

Focused reference for **mikroorm-best-practices**, excerpted from SKILL.md. The skill file remains the canonical guide.

- **Schema-first or entity-first — pick one and commit**; migrations are the reviewed history:

```bash
npx mikro-orm migration:create --path ./migrations
npx mikro-orm migration:up
```

- **Autogenerated migrations reviewed** — they reflect entity current, not intent; backfills hand-written.
- **One conceptual change per migration; `down()` present unless intentional.**
- **`beforeCreate`/`@Property(onCreate)` vs `onUpdate` vs `hidden`/`formula` used for the field's lifecycle, not ad-hoc refactors.**
- **Run migrations in deploy; `synchronize: false` in staging/prod.**

## 6. Transactions & Concurrency

- **UoW flush already wraps changes in a transaction** — for multi-entity invariants use `em.transactional()`/nested `fork`:

```ts
await em.transactional(async (em2) => {
  await em2.nativeInsert(...);
  await em2.nativeUpdate(...);
});
```

- **Optimistic locking via `@Version()`** — a stale write throws `OptimisticLockError` instead of silently overwriting:

```ts
@Version()
version!: number;
```

- **Pessimistic `em.find(..., { lockMode: LockMode.PESSIMISTIC_WRITE })` only for the genuinely racy read-modify-write.**
- **Short transactions**; all slow work before/after the boundary.
