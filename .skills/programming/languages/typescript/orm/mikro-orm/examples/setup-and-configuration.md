# MikroORM Best Practices: 5. Migrations & Schema

## Source guidance

This example applies the **5. Migrations & Schema** section of [SKILL.md](../SKILL.md). Use the excerpt as a pattern and adapt project-specific names, versions, validation, and error handling.

- **Schema-first or entity-first — pick one and commit**; migrations are the reviewed history:
- **Autogenerated migrations reviewed** — they reflect entity current, not intent; backfills hand-written.
- **One conceptual change per migration; `down()` present unless intentional.**
- **`beforeCreate`/`@Property(onCreate)` vs `onUpdate` vs `hidden`/`formula` used for the field's lifecycle, not ad-hoc refactors.**
- **Run migrations in deploy; `synchronize: false` in staging/prod.**

## Example

```bash
npx mikro-orm migration:create --path ./migrations
npx mikro-orm migration:up
```
