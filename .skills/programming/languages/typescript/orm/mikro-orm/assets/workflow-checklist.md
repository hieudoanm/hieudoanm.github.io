# MikroORM Best Practices: Workflow Checklist

A practical run sheet for applying [MikroORM Best Practices](../SKILL.md). Tailor each item to the current project and record evidence where the decision matters.

## Before starting

- [ ] Confirm the task is within this skill's scope.
- [ ] Check applicable versions, project conventions, and prerequisites.
- [ ] Define a measurable outcome and relevant constraints.

## Apply the skill

- [ ] 1. ORM Setup & Context: **One MikroORM instance; a request-scoped EntityManager via fork():**
- [ ] 1. ORM Setup & Context: **Never share one em across concurrent requests** — the identity map + UoW are request-scoped by design
- [ ] 2. Entities: **Decorator entities are the schema and the type:**
- [ ] 2. Entities: **Tight types at the DB boundary** — columnType: "numeric" for money (stay away from float), timestamps via onCreate/onUpdate, varchar(n) bounded
- [ ] 3. Identity Map & Unit of Work: **The identity map: one DB row ⇒ one entity instance per em** — it's a feature, not a leak:
- [ ] 3. Identity Map & Unit of Work: **Tracked objects flush together**: em.persist(x).flush() — or let the UoW collect changes and commit once:
- [ ] 4. Querying & Relations: **em.find with where/orderBy/limit/offset reads as the query; filtering by relation via where: { user: { active: true } }:**
- [ ] 4. Querying & Relations: **populate eagerly for hot paths; never trigger lazy Collection access in a loop (N+1).**
- [ ] 5. Migrations & Schema: **Schema-first or entity-first — pick one and commit**; migrations are the reviewed history:
- [ ] 5. Migrations & Schema: **Autogenerated migrations reviewed** — they reflect entity current, not intent; backfills hand-written
