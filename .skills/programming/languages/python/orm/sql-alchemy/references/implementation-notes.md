# Implementation notes

Focused reference for **sqlalchemy-best-practices**, excerpted from SKILL.md. The skill file remains the canonical guide.

## 4. Migrations & Schema Evolution

- **Alembic as the migration pipeline**, migrations as reviewable code:

```bash
alembic revision --autogenerate -m "add users.profile"
alembic upgrade head
```

- **Review every autogenerated migration** — it reflects current state, not intent; data backfills and default changes need hand-editing.
- **One conceptual change per revision; name them by change, not timestamp.**
- **Indexes for foreign-key and query hot keys declared in the model** (and regenerated), not flown in via ad-hoc SQL.
- **Downgrade paths present for reversible migrations** — never irreversible data-loss on `downgrade`.

## 5. Performance

- **Profile the N+1 first**: enable `echo=True` or `SQLAlchemy echo` in dev — a `select from visits` per user is the #1 read-pattern bug:

```python
stmt = select(User).options(selectinload(User.visits)).where(...)
```

- **Batch writes in single transactions** — one `session.commit()` for many `add`s, not per row (network round trips dominate).
- **`bulk_insert`/`bulk_update_mappings` for pure bulk data** (skip ORM overhead, no relationship bookkeeping) — with a named trade: no lifecycle hooks.
- **Pagination via `limit`/`offset` (or keyset) in SQL** — never `.all()` + Python slicing for large sets.
- **`pool_pre_ping=True` + sensible `pool_size`**; connection pooling is the engine's job, retry the transient deadlock.
