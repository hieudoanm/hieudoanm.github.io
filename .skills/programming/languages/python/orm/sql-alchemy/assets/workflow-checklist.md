# SQLAlchemy Best Practices: Workflow Checklist

A practical run sheet for applying [SQLAlchemy Best Practices](../SKILL.md). Tailor each item to the current project and record evidence where the decision matters.

## Before starting

- [ ] Confirm the task is within this skill's scope.
- [ ] Check applicable versions, project conventions, and prerequisites.
- [ ] Define a measurable outcome and relevant constraints.

## Apply the skill

- [ ] 1. Engine & Session Lifecycle: **One engine per database config; sessions per request/operation, not long-lived:**
- [ ] 1. Engine & Session Lifecycle: **Open a session, do the work, commit/rollback once** — use the context-manager form so close() is guaranteed:
- [ ] 2. Model Design: **Declarative ORM models are the table contract:**
- [ ] 2. Model Design: **Mapped[T]/mapped_column annotations are the schema and the type hint — one source of truth.**
- [ ] 3. Querying: **2.0-style select() everywhere over legacy query():**
- [ ] 3. Querying: **Counts/aggregates in SQL**: func.count(), func.sum() in the select, not len() after loading all rows
- [ ] 4. Migrations & Schema Evolution: **Alembic as the migration pipeline**, migrations as reviewable code:
- [ ] 4. Migrations & Schema Evolution: **Review every autogenerated migration** — it reflects current state, not intent; data backfills and default changes need hand-editing
- [ ] 5. Performance: **Profile the N+1 first**: enable echo=True or SQLAlchemy echo in dev — a select from visits per user is the #1 read-pattern bug:
- [ ] 5. Performance: **Batch writes in single transactions** — one session.commit() for many adds, not per row (network round trips dominate)

## Complete the work

- [ ] Review tradeoffs and failure cases before adopting the result.
- [ ] Run the validation appropriate to the change.
- [ ] Record important assumptions and deviations for future maintainers.
