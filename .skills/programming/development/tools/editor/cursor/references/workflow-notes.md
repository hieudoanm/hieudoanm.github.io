# Workflow notes

Focused reference for **cursor-best-practices**, excerpted from SKILL.md. The skill file remains the canonical guide.

## 2. Rules Files

- **Put the project's conventions in a rules file, not in the prompt.** The rules file is committed, versioned, and applied to every agent invocation; a prompt is neither.
- **Be specific and prescriptive.** "Use existing patterns" produces invented patterns; "components live in `src/components/atoms`, `organisms`, `templates`; a new one goes in the layer it matches" produces a correct location.
- **Include the things an AI gets wrong for this project:** the test command, the build command, the type-check command, the formatting tool, and the file-size and function-size limits this repo enforces.
- **Scope rules to what they govern** — paths, globs, or global — so a styling rule does not get applied to a build script.
- **Rules are code review artefacts.** Change them in a PR, like any other convention, so a disagreement about an AI rule is settled like a disagreement about a lint rule.

```md
<!-- .cursor/rules/project.mdc -->
---
description: Project conventions for agents working in this repo
globs: **/*
---

# Commands
- Install: `pnpm install`
- Type check: `pnpm typecheck` (must pass before commit)
- Test: `pnpm test`
- Format: `pnpm format`

# Structure
- `src/components/atoms/` — single-purpose, no app imports
- `src/components/templates/` — page-level composition
- `src/games/<name>/` — `index.tsx` for UI, `utils.ts` for pure logic, zero UI imports in utils

# Rules
- No secrets in source; read from env through the existing config module
- Never widen a TypeScript type to silence an error; fix the type
- Files ≤ 200 lines, functions ≤ 30 lines
- No new runtime dependency without an ADR
```

## 3. Agent Mode Boundaries

- **Scope a task before you start it.** A precise, bounded request ("add a pure function and its tests to `utils.ts`, do not change the component") produces a reviewable diff; a broad one produces a rewrite.
- **Ask for a plan first on anything non-trivial,** and reject the plan before code is written if the approach is wrong. A wrong plan implemented competently is still wrong.
- **Let the agent edit a bounded set of files,** then read the actual diff in your VCS — not the editor's summary of what it did. The summary is generated by the same system that made the change.
- **Turn off auto-apply for anything that touches configuration, CI, or dependency manifests,** and require an explicit action for those. A silently modified lockfile or a loosened lint rule is a supply-chain event.
- **Do not let it run migrations, deploys, or anything with side effects outside the repo** without reviewing the command first.
