Garph is a **type-safe, schema-first GraphQL framework for TypeScript** (by Dax Raad). It lets you **define GraphQL schemas with full TypeScript type inference and no code generation step**, perfect for library/graphQL-driven TypeScript projects.

## 1. Core Concepts

- **Schema-first in TS**: use Garph types (`g.string()`, `g.int()`, `g.ref(...)`) to build schema directly — the TS types are generated by reading the schema at compile-time, no CLI/codegen.
- **Automatic inference**: TypeScript infers the types for resolvers from the schema object (`g.type(...)`) — wrong resolver signatures fail compilation.
- **Resolver**: objects keyed by field names with functions returning inferred types.
- Composes with NodeGraphQL/GraphQL-Yoga.

## 2. Setup

- Deps: `garph`, `graphql`, and a server adapter (pairs with `graphql-yoga` or an HTTP server via `graphql`).
- Build a `g.schema(...)` and a resolver map, then `g.resolve()` to get executable schema.

## 3. Definitions

- Scalars: `g.string()`, `g.int()`, `g.float()`, `g.boolean()`, `g.id()`.
- Types: `g.type('User', { name: g.string(), age: g.int().optional() })` (`Nullable`/`optional` modifiers).
- Inputs: `g.input('UserInput', { name: g.string() })` for mutations args.
- Enums: `g.enum('Role', [...], { 'ADMIN': 'admin', ... })` — last arg maps names to values.
- Extensions: `g.ref('User')` to reference types in fields; `g.list(...)` for arrays.

## 4. Resolvers

- Pass a resolver map aligned with schema keys: `const resolvers = { Query: { hello: () => 'hi' } }`.
- Typed args: read `args` from resolver signature — TS knows their types.
- Async returns automatic.
- Errors: throw GraphQL-safe errors; provide consistent return types against schema.

## 5. Type Safety Workflow

- The compiler checks that resolver return types match schema — drift caught at dev time, not runtime.
- Smaller schemas: prefer explicit types over inference magic for complex fields (mitigate `any`/`unknown` misunderstandings).
- Combine with Yoga for middleware, plugins, subscriptions.

## 6. Common Pitfalls

- Forgetting the resolver shape must mirror schema exactly (untyped key mismatch → runtime error or TS error).
- Relying on implicit `any` in inference for unions/interfaces loops — write them explicitly when tricky.
- Not leveraging `g.enum(..., {valueMap})` leading to string-only enums losing runtime values.
- Over-abusing `g.ref` circular references without `g.lazy(...)` for self-references.

## General Rules of Thumb

- Write the schema once, let Garph infer; keep resolver map structure aligned 1:1.
- Use explicit input types for all mutation arguments.
- Pair with `graphql-yoga` for a full production server (middleware, subscriptions, plugins).
- Verify types with `tsc --noEmit` before shipping.

## Quick-Start Checklist

- [ ] `npm i garph graphql` (and `graphql-yoga` for the server).
- [ ] Define schema via `g.type()`/`g.input()`/`g.enum()` with nullability.
- [ ] Build resolver map aligned with the schema structure.
- [ ] Execute with `g.resolve(schema, resolvers)` → pass to Yoga.
- [ ] Run `tsc --noEmit` to check inferred resolver types.
- [ ] Add Yoga plugins: context/auth, error handling, subscriptions.
